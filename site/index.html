Models learn a language that the run invents.

babel-bench generates a programming language from a seed, gives the model only that language's manual, and grades the answer by running it in the language's own interpreter.

Try the playground See the evidence Source on GitHub

Static benchmarks end up in training data.

A coding benchmark with a fixed set of problems gets copied, discussed and trained on, then saturates. A score on it tells you how much the model has memorised.

babel-bench removes the memory route. Every run uses a language that did not exist before it. The model can reach a correct answer only by reading the manual it is given, and nothing it learned before the run contains that language.

How a run works

  1. Generate. A seed fixes the keywords, block delimiters, operator spellings, precedence, call style, index base, division and modulo rounding, truthiness and the and/or result.

  2. Document. The manual is built from examples. Each example is written as a syntax tree, printed in the language, executed, and the output the interpreter produced is what the manual states.

  3. Ask. The model gets the manual and one task: predict the output of a program, translate a Python function, write a function from a spec, or fix a program with one injected bug.

  4. Grade. The answer is parsed by that language's own parser and run against hidden tests in the interpreter. The interpreter has step, depth, size, output and time limits.

Architecture

One shared AST and one interpreter give the meaning of every program. Each generated language has its own lexer, parser and printer, so a grammar bug cannot change what a program means.

The model is an adapter. Anthropic, any OpenAI-compatible endpoint, any shell command, a perfect oracle and a naive baseline all plug into the same harness, which resumes finished cells and writes one JSON line per cell.

Playground

Pick a seed or roll one, read that language's manual, then write a program for a code task. The program is parsed and run by the same interpreter the benchmark uses, against hidden tests. You get pass or fail, the feedback the harness would give a model, and what your program prints.

Predict tasks are not graded here. Read the program and work out its output yourself.

Limitations

    
    
      
  • One small live sample. The Anthropic and OpenAI-compatible adapters are implemented, but they have not been run against a live endpoint.
    • 
      
  • 24 templates. Tasks are small and do not yet span several functions.
    • 
      
  • Confidence intervals treat cells as independent. Cells that share a language or task are correlated, so the intervals are optimistic.
    • 
      
  • Two call styles, not three. Infix call syntax is not generated.
    • 
      
  • The interpreter runs in-process for grading. A language with host-facing features would need a sandboxed subprocess.
    • 
      
  • Known gap: in newline-terminated languages, else and the block opener must share a line with the statement. A model that writes Allman-style braces gets a parse error.
    • 
      
  • The playground API runs as a Vercel Python function. Its per-IP rate limits and concurrency cap live in each function instance, so they are weaker than in a long-running container. The hard per-request limits (wall-clock kill, memory cap, interpreter step and time limits) do not depend on instance state.
